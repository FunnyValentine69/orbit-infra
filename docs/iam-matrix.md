# IAM action-condition matrix

This is the executable P0-3d specification for the ten bootstrap permission documents, their principal bindings, the three GitHub OIDC trust documents, and the KMS signing-key resource policy. It records policy evaluation cases; it does not claim AWS enforcement has run. The first seven cells of every statement row, and all five cells of every binding row, are generated from the post-bootstrap-apply LocalStack plan and are drift-locked by `tests/iam-matrix-contracts.sh`. Empty-string and null `permissions_boundary` values are both canonicalised as `none` by `scripts/iam-matrix-inventory.sh`.

Generator commit: `3f744c7` (the commit that added `scripts/iam-matrix-inventory.sh`; the cells below were generated from a plan rendered at that commit). Canonical regeneration:

```bash
make bootstrap-apply TARGET=localstack
POLICY_SIZE_PLAN_JSON_OUT=<plan.json> bootstrap/policy-size-check.sh
bash scripts/iam-matrix-inventory.sh <plan.json>
bash tests/iam-matrix-contracts.sh <plan.json>
```

Only the inventory and binding cells are generated. Cases, threat-model mappings, evidence, evidence ceilings, and the execution protocol are reviewed by hand.

## Evidence legend

Evidence applies per case, and each row is only as strong as its least-supported case.

- `CODE-ONLY`: executable case authored but not executed against the relevant AWS evaluator or service.
- `AWS-SIMULATED <date> <pointer>`: IAM policy simulator execution against the real account. This proves policy evaluation, not service enforcement.
- `AWS-VERIFIED <date> <pointer>`: recorded live call under the real principal.
- `CONFIG-COMPARED <date> <pointer>`: deployed policy fetched and canonically equal to the rendered policy where one statement's causal effect cannot be isolated.
- `N/A(<reason>)`: no executable case exists in principle. A possible but unimplemented case remains `CODE-ONLY`.

When P0-3d runs, edit only the Evidence cell. Each case id receives its own label and pointer. A row reaches `AWS-VERIFIED` only when every executable case has live evidence; otherwise its row label is the minimum evidence level represented in the cell.

## Condition truth tables

Every variant holds all other condition keys at satisfying values. When overlapping Deny statements could produce the same decision, require `MatchedStatements` attribution to the Sid and statement position, use an isolated `simulate-custom-policy` document, or suffix the case variant with `effective`; effective-policy evidence cannot promote the row above `AWS-SIMULATED`.

| Effect | Operator | Required variants and decisions |
|---|---|---|
| `Allow` | `StringEquals` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `StringLike` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `ForAnyValue:StringEquals` | `one-matching=allowed; none-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `ArnLike` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Deny` | `StringNotLike` | `outside-set=explicitDeny; inside-set=not-denied-by-this-statement; absent=explicitDeny` |
| `Deny` | `Null` | `absent=explicitDeny; present=not-denied-by-this-statement` |
| `Deny` | `StringNotEquals` | `different=explicitDeny; equal=not-denied-by-this-statement; absent=explicitDeny` |

The table is exhaustive for the current inventory. `tests/iam-matrix-contracts.sh` fails if a statement introduces another operator. Caller-supplied simulator context cannot prove that a service supplies a condition key. In particular, `Ec2ModifyDeleteWithResourceTag` for `ec2:ReplaceRoute`, `ec2:ReplaceRouteTableAssociation`, and `ec2:ModifySecurityGroupRules`, and `ElbModifyDeleteWithResourceTag` for `elasticloadbalancing:RegisterTargets` and `elasticloadbalancing:DeregisterTargets`, can reach only `AWS-SIMULATED` under this protocol. Service enforcement remains the row-5 residual under P5-20 unless a separately authorised, rollback-controlled live test is recorded.

## Permission, key-policy, and trust statements

The action placeholder `ALL` means that the case is repeated for every action in the row's canonical Action array. A row resource placeholder means the service-appropriate ARN from that row; actions requiring different resource types use separate invocations. Identity-policy rows spell out `aws iam simulate-principal-policy --policy-source-arn`, `--action-names`, `--resource-arns`, and condition-specific `--context-entries`; each `ALL` case expands to one invocation per action and resource type. Boundary rows use `aws iam simulate-custom-policy --policy-input-list` for the matching identity grant plus `--permissions-boundary-policy-input-list` for the full six-statement cap.
Each context placeholder expands to `ContextKeyName=<condition key>,ContextKeyValues=<variant value>,ContextKeyType=string`; absent variants omit that entry.

## P0-3d execution protocol

Prerequisites are P0-3b, an applied real-AWS bootstrap, the three GitHub role secrets, and an operator identity allowed to call `iam:SimulatePrincipalPolicy`, `iam:SimulateCustomPolicy`, `iam:GetContextKeysForPrincipalPolicy`, and `kms:GetKeyPolicy`.

1. Fetch the deployed customer-managed, inline, trust, and key policies and retain redacted canonical copies with the gate evidence.
2. For every action in every Sid'd row of the ten permission documents, execute the row's positive, negative, resource, and per-condition variants. Use principal simulation for the nine attached documents and custom simulation for the boundary. Record decision, context, resource, policy id, statement position, date, and evidence pointer. Attribute overlapping Deny decisions through `MatchedStatements` or an isolated custom policy.
3. Run the three `oidc-smoke.yml` run types for main-ref success, same-repository pull-request refusal, and non-main-ref refusal. Add the deliberate wrong-audience attempt and exact decoded-`sub` assertions tracked by P5-28 before promoting those cases.
4. Canonically compare `aws kms get-key-policy` with the rendered key policy. The only live KMS calls in this gate are plan-reader `DescribeKey` and `GetPublicKey`, deployer and plan-reader denied `Sign`, and publisher `Sign` followed by `Verify` on the fixed gate digest.
5. Limit live spot checks to read-only `Describe`, `List`, and `GetObject` operations on the scoped state resources plus the listed KMS calls. Make no live mutating service call as part of this gate.
6. Edit only each row's Evidence cell with per-case date and pointer. A row's label is the minimum across its cases; simulation never proves service-side condition-key enforcement.

Known gap: `ReadOnlyAccess` is AWS-managed, so this contract fixes its attachment but not its changing grant content. P0-3d remains open until every executable case is recorded at its required evidence level; P5-19 closes when this specification and drift contract are authored.
