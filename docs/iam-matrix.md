# IAM action-condition matrix

This is the executable P0-3d specification for the ten bootstrap permission documents, their principal bindings, the three GitHub OIDC trust documents, and the KMS signing-key resource policy. It records policy evaluation cases; it does not claim AWS enforcement has run. The first seven cells of every statement row, and all five cells of every binding row, are generated from the post-bootstrap-apply LocalStack plan and are drift-locked by `tests/iam-matrix-contracts.sh`. Empty-string and null `permissions_boundary` values are both canonicalised as `none` by `scripts/iam-matrix-inventory.sh`. Source mode mechanically validates case structure, strict per-case decision text, simulator mode and bound-role ARNs, exact `N/A` bodies and eligibility, and evidence-label syntax; evidence labels are recorded facts from P0-3d and their truth cannot be validated mechanically. Known gap: source mode is Sid-keyed and does not parse HCL policy fields, while the exact plan-mode comparison runs only in the same-repository `plan-localstack` job, so field-level drift in a fork PR can remain until a same-repository run (P5-31).

Generator commit: `3f744c7` (the commit that added `scripts/iam-matrix-inventory.sh`; the cells below were generated from a plan rendered at that commit). Canonical regeneration:

```bash
make bootstrap-apply TARGET=localstack
POLICY_SIZE_PLAN_JSON_OUT=<plan.json> bootstrap/policy-size-check.sh
bash scripts/iam-matrix-inventory.sh <plan.json>
bash tests/iam-matrix-contracts.sh <plan.json>
```

Only the inventory and binding cells are generated. Cases, threat-model mappings, evidence, evidence ceilings, and the execution protocol are reviewed by hand.

## Render for the real account

The committed matrix deliberately uses the LocalStack placeholder account `000000000000` in every account-bearing ARN and `us-east-1` in every region-bearing ARN. The source contract enforces the account placeholder so the substitution is total; plan inventory drift-locks the generated ARN cells. Before P0-3d execution, render a temporary execution copy for the deployed account and region. Never edit the committed matrix for real-account execution.

```bash
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
REGION="${AWS_REGION:-us-east-1}" # set AWS_REGION to the deployed region if it differs
EXECUTION_COPY="$(mktemp "${TMPDIR:-/tmp}/orbit-iam-matrix-real.XXXXXX")"
sed -e "s/000000000000/$ACCOUNT_ID/g" -e "s/us-east-1/$REGION/g" \
  docs/iam-matrix.md > "$EXECUTION_COPY"
```

Execute the protocol from `$EXECUTION_COPY`; retain it only in the redacted evidence store, never in the repository.

## Evidence legend

Evidence applies per case, and each row is only as strong as its least-supported case.

- `CODE-ONLY`: executable case authored but not executed against the relevant AWS evaluator or service.
- `AWS-SIMULATED <date> <pointer>`: IAM policy simulator execution against the real account. This proves policy evaluation, not service enforcement.
- `AWS-VERIFIED <date> <pointer>`: recorded live call under the real principal.
- `CONFIG-COMPARED <date> <pointer>`: deployed policy fetched and canonically equal to the rendered policy where one statement's causal effect cannot be isolated.
- `N/A(<reason>)`: no executable case exists in principle. A possible but unimplemented case remains `CODE-ONLY`.

When P0-3d runs, edit only the Evidence cell. Each case id receives its own label and pointer. A row reaches `AWS-VERIFIED` only when every executable case has live evidence; otherwise its row label is the minimum evidence level represented in the cell.

## Condition truth tables

Every variant holds all other condition keys at satisfying values. When overlapping Deny statements could produce the same decision, require `MatchedStatements` attribution to the Sid and statement position, use a `simulate-custom-policy` document containing only the target statement, or suffix the case variant with `effective`; effective-policy evidence cannot promote the row above `AWS-SIMULATED`. A negative Allow variant is masked when any other Allow or Deny statement bound to the same role has an Action pattern covering at least one repeated case action and a Resource pattern overlapping the row resources. Same-document statements, inline policies, attached policies, `*`, and prefix wildcards are included; uncertain wildcard intersections are treated as overlapping. For plan-reader, the attached AWS-managed `ReadOnlyAccess` is conservatively modeled as allowing every `Describe*`, `Get*`, and `List*` action on `*`. Every masked negative must use the isolated form defined below.

| Effect | Operator | Required variants and decisions |
|---|---|---|
| `Allow` | `StringEquals` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `StringLike` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `ForAnyValue:StringEquals` | `one-matching=allowed; none-matching=implicitDeny; absent=implicitDeny` |
| `Allow` | `ArnLike` | `matching=allowed; non-matching=implicitDeny; absent=implicitDeny` |
| `Deny` | `StringNotLike` | `outside-set=explicitDeny; inside-set=not-denied-by-this-statement; absent=explicitDeny` |
| `Deny` | `Null` | `absent=explicitDeny; present=not-denied-by-this-statement` |
| `Deny` | `StringNotEquals` | `different=explicitDeny; equal=not-denied-by-this-statement; absent=explicitDeny` |

For `ForAnyValue` operators, present condition keys are supplied as `ContextKeyType=stringList`; the one-matching case includes one matching value among multiple non-matching values.

### Resource-scope truth table

| Effect | Scope | Required variant and decision |
|---|---|---|
| `Allow` | `Resource cell is not * and has no full-type wildcard` | `resource:nonmatching=implicitDeny` |
| `Allow` | `Resource pattern is a full-type wildcard` | `resource:nonmatching=N/A(non-empty reason)` |
| `Allow` | `Resource cell is * and Condition is none (negative case)` | `none:non-resource=N/A(non-empty reason)` |
| `Deny` | `Resource cell is * (positive case)` | `none:non-protected-resource=N/A(non-empty reason)` |

The tables are exhaustive for the current inventory. A full-type wildcard has a resource path of exactly `*` after its type segment, such as `hostedzone/*`; only that shape may use `N/A(<reason>)` for `resource:nonmatching`. `tests/iam-matrix-contracts.sh` fails if a statement introduces another operator or a resource-scoped Allow omits its same-action, non-matching-resource case. Caller-supplied simulator context cannot prove that a service supplies a condition key. In particular, `Ec2ModifyDeleteWithResourceTag` for `ec2:ReplaceRoute`, `ec2:ReplaceRouteTableAssociation`, and `ec2:ModifySecurityGroupRules`, and `ElbModifyDeleteWithResourceTag` for `elasticloadbalancing:RegisterTargets` and `elasticloadbalancing:DeregisterTargets`, can reach only `AWS-SIMULATED` under this protocol. Service enforcement remains the row-5 residual under P5-20 unless a separately authorised, rollback-controlled live test is recorded.

## Permission, key-policy, and trust statements

The action placeholder `ALL` means that the case is repeated for every action in the row's canonical Action array. A row resource placeholder means the service-appropriate ARN from that row; actions requiring different resource types use separate invocations. Every executable identity-policy case spells out `aws iam simulate-principal-policy --policy-source-arn` with its exact bound role ARN, `--action-names`, `--resource-arns`, and condition-specific `--context-entries`; each `ALL` case expands to one invocation per action and resource type. The exception is a masked negative, whose complete body has the exact form `aws iam simulate-custom-policy --policy-input-list '<a policy document containing only the <row Sid> statement>' --action-names ... --resource-arns ... [--context-entries ... | no --context-entries]; expect implicitDeny (isolated statement; principal simulation is masked by <Sid> in <document>)`, or the attribution `masked by ReadOnlyAccess` for that managed policy. The `masked by` parenthetical is statement attribution, not a second decision. An attribution fallback on an otherwise principal-simulated case may mention custom simulation only as `or an isolated simulate-custom-policy containing only the <row Sid> statement` after that principal call. Boundary rows use `aws iam simulate-custom-policy --policy-input-list` for the matching identity grant plus `--permissions-boundary-policy-input-list` for the full six-statement cap.
Each scalar context placeholder expands to `ContextKeyName=<condition key>,ContextKeyValues=<variant value>,ContextKeyType=string`; `ForAnyValue` cases use the `stringList` values specified above, and absent variants omit that key.

## P0-3d execution protocol

Prerequisites are P0-3b, an applied real-AWS bootstrap, the three GitHub role secrets, and an operator identity allowed to call `iam:SimulatePrincipalPolicy`, `iam:SimulateCustomPolicy`, `iam:GetContextKeysForPrincipalPolicy`, and `kms:GetKeyPolicy`.

1. Render `$EXECUTION_COPY` with the real `ACCOUNT_ID` and deployed `REGION` exactly as specified in **Render for the real account**; execute every remaining step from that copy and never edit the committed matrix.
2. Fetch the deployed customer-managed, inline, trust, and key policies and retain redacted canonical copies with the gate evidence.
3. For every action in every Sid'd row of the ten permission documents, execute the row's positive, negative, resource, and per-condition variants. Use principal simulation for unmasked cases in the nine attached documents, isolated single-statement custom simulation for masked negatives, and identity-plus-boundary custom simulation for the boundary. Record decision, context, resource, policy id, statement position, date, and evidence pointer. Attribute overlapping Deny decisions through `MatchedStatements` or the prescribed isolated custom policy.
4. Run the three `oidc-smoke.yml` run types for main-ref success, same-repository pull-request refusal, and non-main-ref refusal. Add the exact decoded-`sub` assertions tracked by P5-28 before promoting those executable cases; keep the separate wrong-audience attempt labelled as a provider-level client-ID-list negative, not evidence for the trust statement's `aud` condition.
5. Canonically compare `aws kms get-key-policy` with the rendered key policy. The only live KMS calls in this gate are plan-reader `DescribeKey` and `GetPublicKey`, deployer and plan-reader denied `Sign`, and publisher `Sign` followed by `Verify` on the fixed gate digest.
6. Limit live spot checks to read-only `Describe`, `List`, and `GetObject` operations on the scoped state resources plus the listed KMS calls. Make no live mutating service call as part of this gate.
7. Edit only each row's Evidence cell in the committed matrix with per-case date and pointer after redacting real-account details. A row's label is the minimum across its cases; simulation never proves service-side condition-key enforcement.

Known gap: `ReadOnlyAccess` is AWS-managed, so this contract fixes its attachment but not its changing grant content. P0-3d remains open until every executable case is recorded at its required evidence level; P5-19 closes when this specification and drift contract are authored.
